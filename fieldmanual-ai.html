How this demo retrieves text

The query and each excerpt are lowercased and tokenized. Common question words are removed. Excerpts are ranked by the fraction of unique query tokens they contain. A score is a word-overlap measure, not semantic similarity or an answer-confidence probability. No LLM generates an answer.

DESIGN, WORKING DEMO & TESTING

Project overview

Equipment manuals and maintenance procedures are difficult to search under time pressure. This browser prototype demonstrates traceable technical-document retrieval with a bundled library and clickable source excerpts.

Implementation details

  • Use three fictional maintenance-related documents with six inspectable text excerpts.
  • Tokenize questions, remove common stopwords, and rank evidence by lexical overlap.
  • Provide page and section citations with accessible source dialogs.
  • Allow configurable top-k retrieval and return an explicit no-evidence state rather than inventing instructions.

Testing & evaluation

  • Run known safety, calibration and inspection questions and inspect matching source excerpts.
  • Check that irrelevant queries produce no cited evidence.
  • A production RAG system needs PDF ingestion, embeddings, LLM generation, citation fidelity checks and specialist validation, none of which are implemented by this browser demo.

Architecture

Field question→Local text search→Ranked manual excerpts→Page citations→Evidence review

Demo boundaries

The demo searches fictional, bundled plain-text excerpts by token overlap. It does not parse uploaded PDFs, query vectors, call an LLM, or provide trustworthy operational safety instructions. It is a user-interface prototype for a more complete system.
