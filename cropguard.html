DESIGN, WORKING DEMO & TESTING

Project overview

A field-friendly plant disease screening workflow needs consistent image input handling, credible predictions and predictable API responses. This page explores the serving contract through a local simulation built around a fictional tomato-leaf sample.

Implementation details

  • Validate an example leaf-image identifier, requested model version, and confidence threshold.
  • Explore deterministic disease-region examples, bounding boxes, and structured JSON output.
  • Test malformed requests, invalid thresholds, unsupported models, and confidence-based filtering.
  • Describe where FastAPI, ONNX Runtime, Docker, preprocessing and model monitoring fit in a deployable implementation.

Testing & evaluation

  • Exercise valid and invalid payloads with consistent example responses.
  • Check filtered detections at low and high confidence thresholds.
  • No training accuracy, disease diagnosis, live inference latency, or hosted API is implied by this educational simulation.

Architecture

Leaf image request→Input validation→ONNX model (system design)→Confidence filtering→Structured disease labels

Demo boundaries

This portfolio demo validates JSON and filters bundled fictional detections in JavaScript. It does not upload real images, run an ONNX model, start FastAPI or Docker, or provide actual plant-health diagnoses.
